## Ollama + Gemma 4 Setup on Apple Silicon Mac mini
- **URL:** https://gist.github.com/greenstevester/fc49b4e60a4fef9effc79066c1033ae5
- **Category:** AI/ML, Local LLM, Infrastructure, macOS
- **Description:** April 2026 practical guide for running Ollama + Gemma 4 12B on Apple Silicon Mac mini. Covers auto-start, preload, keep-alive configuration, and memory optimization for production use.
- **Hardware Requirements:**
  - Mac mini with Apple Silicon (M1/M2/M3/M4/M5)
  - At least 16GB unified memory for Gemma 4 (8B default)
  - macOS with Homebrew installed
- **Installation:**
  - `brew install --cask ollama-app`
  - Installs Ollama.app + CLI at /opt/homebrew/bin/ollama
  - Uses MLX backend automatically on Apple Silicon
- **Model Sizing:**
  - Default gemma4:latest (8B, Q4_K_M, ~9.6GB) — recommended for 24GB machines
  - 26B variant consumes ~17GB — causes swapping issues under concurrent load
- **Keep-Alive Configuration:**
  - Launch agent: `com.ollama.preload-gemma4.plist`
  - Runs every 5 minutes to keep model warm
  - `OLLAMA_KEEP_ALIVE="-1"` for permanent loading
- **Memory Optimizations (Ollama v0.20.0):**
  - Lower memory utilization: cache reuse across conversations
  - Intelligent checkpoints: snapshots at strategic prompt locations
  - Smarter eviction: shared prefixes survive longer
  - NVFP4 format support for reduced memory bandwidth
- **API Endpoint:** http://localhost:11434 (OpenAI-compatible)
- **Key Commands:**
  - `ollama list` — downloaded models
  - `ollama ps` — running models & memory usage
  - `ollama run gemma4:latest` — interactive chat
  - `ollama stop gemma4:latest` — unload from memory
- **Added:** 2026-04-05

## HiClaw - Collaborative Multi-Agent OS
- **URL:** https://github.com/agentscope-ai/HiClaw
- **Category:** AI Agents, Multi-Agent Systems, Infrastructure, Matrix Protocol
- **Description:** Open-source Collaborative Multi-Agent OS for transparent, human-in-the-loop task coordination via Matrix rooms. Manager-Workers architecture where Manager Agent coordinates multiple Worker Agents.
- **Key Features:**
  - 🧬 Manager-Workers Architecture: Agents manage other Agents, eliminating need for human oversight of individual Workers
  - 🦞 Customizable Agents: OpenClaw, Copaw, NanoClaw, ZeroClaw runtimes
  - 📦 MinIO Shared File System: Inter-agent info exchange, reduces token consumption
  - 🔐 Higress AI Gateway: Centralized traffic management, enterprise-grade credential security
  - ☎️ Element IM Client + Tuwunel IM Server: Matrix protocol-based, no enterprise approvals needed
- **Security Model:**
  - Workers operate with consumer tokens only
  - Real credentials (API keys, GitHub PATs) stay in Higress gateway
  - Workers and attackers cannot see real credentials
- **Human-in-the-Loop:**
  - Every Matrix room includes human, Manager, and relevant Workers
  - Watch everything in real-time, intervene at any time
  - No black boxes, no hidden agent-to-agent calls
- **Deployment:** One command setup (`curl | bash`) — AI gateway, Matrix server, file storage, web client, Manager Agent
- **Requirements:** Docker, 2 CPU + 4GB RAM min (4 cores + 8GB recommended for multiple Workers)
- **Architecture:**
  - Higress AI Gateway: LLM proxy, MCP Server hosting, credential management
  - Tuwunel: Self-hosted Matrix IM server
  - Element Web: Browser client, zero setup
  - MinIO: Centralized file storage (Workers are stateless)
  - OpenClaw: Agent runtime with Matrix plugin
- **Worker Runtimes:**
  - CoPaw: ~150MB memory (vs ~500MB OpenClaw), local host mode for browser automation
  - ZeroClaw: Rust-based, 3.4MB binary, goal <100MB per Worker
- **Skills Ecosystem:** Workers pull from skills.sh (80,000+ community skills)
- **License:** Apache 2.0
- **Added:** 2026-04-05
